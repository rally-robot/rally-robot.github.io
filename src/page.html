    Abstract

    Robotic harnesses let foundation models solve physical tasks through generated code policies. However, these policies still struggle to remain robust to variations in objects and their locations, camera views, or backgrounds, and to generalize across tasks. In this paper, we argue that refining a code policy only on the given task and scenes leaves failures in new scenes or tasks undetected until deployment. Inspired by how coaches rally with players to expose weaknesses and teach new skills, we introduce RALLY, a harness-agnostic framework that structures policy refinement as a two-player game. Alice is an additional agent that reads the policy of an existing harness (Bob) and proposes environment variations or related tasks on which Bob refines it.

    We consider two settings. To improve policy robustness, Alice acts as an adversary and proposes task-preserving variations (e.g., camera views or object positions) meant to break the current policy. To help the policy generalize across tasks, Alice acts as a collaborator and proposes related tasks (e.g., manipulating a different object), and Bob extends the same policy to solve each new task.

    We refine all policies on LIBERO. With Alice as an adversary, RALLY raises zero-shot success for ASPIRE (+19.9%), RHO (+15.0%), and GaP (+13.7%) on LIBERO-Pro, LIBERO-Plus, and LIBERO-MAX. With Alice as a collaborator, policies refined on one task of a suite reach 62.8% average success on the suite's other tasks, compared with 11.7% without Alice. Notably, RALLY enables Sonnet 5.5 to outperform Fable 5.2 at a third of its cost, and our simulation-refined policies succeed in 92.5% of real-robot trials on new tasks.

    Method

    Alice challenges Bob during refinement

    Bob is an existing robotic harness, such as ASPIRE, RHO or GaP, used as-is: it writes a code policy, runs it, and repairs it from the execution traces. Alice is a second agent that reads Bob's code and traces, finds where the policy is likely to fail, and builds a new scene or task in simulation with generic scene functions. Bob then refines the same policy on it, one proposal per cycle.

    Adversarial Alice · robustness

    Find the scene that breaks the policy

    Alice proposes
    Variations of the same task meant to make the current policy fail, such as a new camera view, moved objects, or a change during execution.
    Bob
    Repairs the same policy on each scene Alice proposes.
    Tested on
    LIBERO-Pro, LIBERO-Plus and LIBERO-MAX, zero-shot.

    Cooperative Alice · generalization

    Propose the next task to practice

    Alice proposes
    Related tasks one step beyond what the policy solves: a different object, a different target, or a new combination of sub-tasks. When a long task fails, the trace shows which sub-tasks already succeed, so Alice can isolate the failing one.
    Bob
    Starts from the policy of one task of a LIBERO suite and extends that same policy to each task Alice proposes.
    Tested on
    The other nine tasks of the suite.

    RALLY-Bob · a harness built for Alice

    Write every decision as an explicit rule

    The policy
    A sequence of actions, such as acquiring and placing an object. Each action holds if-else decisions that choose what the robot does next from observations of the scene. For example, after a lift, the policy checks whether the bottle rose; if not, it opens the gripper, retreats, and retries with a different grasp depth.
    Why it helps Alice
    Alice can read code from any harness, but explicit rules show which physical situation selects which action. Each rule links a possible weakness to a scene that tests it: if a recovery retries a failed grasp from the same direction, adversarial Alice can propose a placement that blocks that approach. Cooperative Alice can propose related tasks that reuse existing actions and need few code changes.

    Real robot

    From simulation to a Franka arm

    Bob refines every policy only in simulation, starting from task 0 of LIBERO-Object, and the policy then runs on a Franka arm with a scene camera and a wrist camera, 20 trials per experiment. The adversarial tests occlude the object from the scene camera or move the target during execution; the cooperative tests change the object, the target, or both.

    Short-horizon task

    Long-horizon task

    The robot removes the object in a container and places a second object there. Bob refines on a replace task built for this experiment, outside LIBERO, and each Alice plays 16 cycles. The last test starts instead from task 9 of LIBERO-10, putting a mug in the microwave and closing it.
